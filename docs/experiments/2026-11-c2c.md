## Before each run: the 24-hour check

Replace `<PREVIOUS-RUN-ID>` with the run id of the previous counted C-2c run, from the schedule above.

```powershell
uv run cernis runs --format json --output reports\c2c-runs.json
$runs = (Get-Content -Raw -Encoding UTF8 reports\c2c-runs.json | ConvertFrom-Json).runs
$previous = $runs | Where-Object { $_.id -eq '<PREVIOUS-RUN-ID>' }
$hours = ([DateTimeOffset]::UtcNow - [DateTimeOffset]::Parse($previous.started_at)).TotalHours
"{0:N1} hours since run {1} started at {2}" -f $hours, $previous.id, $previous.started_at
```

Run only if it prints 24.0 or more (allow a few minutes' margin, since the run starts a little after the check). If `$previous` is empty, the run id was mistyped.

## After each run: record it

Replace the report's file name with the one the run just wrote:

```powershell
$report = Get-Content -Raw -Encoding UTF8 reports\2026-11-18-c2c-run-2.json | ConvertFrom-Json
"Run id: {0}" -f $report.run.id
"Started: {0}" -f $report.run.started_at
"Tip: {0} {1}" -f $report.run.ledger.tip.sequence, $report.run.ledger.tip.entry_hash
$report.receipts | Group-Object status_code | Sort-Object Name | Select-Object Name, Count
uv run cernis store verify
```

Write the run id, the start time, the tip's sequence, and the receipt counts (200, 304, and the rest, by status) into the schedule. `cernis store verify` must end with `Result: VERIFIED`; if it does not, stop and record why. Every receipt should be a 200 or a known non-200 (C-2b saw one 403 and one 404); a 304 means the cache directory was not fresh.

It lists nothing when all 40 diffs found no change. Each file it lists holds a change event, unless it is `CHECKER` throughout, or a reader comment excludes it (below). A `RESOURCE` cause counts as a change event (DESIGN.md section 8, the scope note).

## Reader comments

A new comment on one of the ten pages changes that page. For each page change in a listed diff, open that page and look at its comments:

- If a comment was posted between the two runs' start times (from the schedule), that page's diff for that pair is **excluded**. Record it as "changed by a reader comment", with the comment's timestamp only: never its text, never its author.
- The page's other diffs still count.
- If more than two of the ten pages are excluded this way, C-2c is **incomplete**.

## The result

After the four diffs, C-2c **holds** if no change event remains, is **falsified** otherwise, and is **incomplete** if the window was broken (an edit or a post) or more than two pages were excluded by reader comments. The result goes in DESIGN.md section 8 in the session that records it, with each change event's diff, page, class or cause, and evidence.
